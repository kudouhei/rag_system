# 代码评审与分支保护（Code Review & Branch Protection）

## 1. 分支策略
- `main`/`master` 为受保护分支，禁止直接 push，必须通过 Pull Request 合并
- 功能分支命名规范：`feature/*`、`fix/*`、`hotfix/*`

## 2. 分支保护规则
- 至少 1 名（核心服务要求 2 名）Reviewer 批准后才能合并
- 必须通过 CI（单测、Lint、安全扫描）后才允许合并
- 禁止 force push 到受保护分支
- 涉及权限模型、支付、加密相关代码需安全团队额外评审

## 3. 代码仓库访问权限
- 仓库访问需通过权限申请流程开通（只读/写入/管理员三档）
- SSH Key 是访问 Git 仓库的常见方式：需要将公钥上传到代码平台账号设置中
- 常见访问问题（如 `Permission denied (publickey)`）通常是本地 SSH Key 未正确配置或未上传到平台

## 4. 评审内容清单
- 逻辑正确性、边界条件、性能影响
- 是否引入新的敏感数据处理、是否遵循最小权限原则
- 是否有对应的单元测试/集成测试

## 5. 合并后
- 合并到 `main` 会自动触发 CI/CD 流水线进入发布流程
- 紧急修复（hotfix）可走加速评审通道，但仍需至少 1 名 Reviewer
