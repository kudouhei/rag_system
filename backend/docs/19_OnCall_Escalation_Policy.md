# 值班与升级策略（On-call & Escalation）

## 1. 值班轮换
- 一线（Primary）、二线（Secondary/Backup）、经理层（Manager Escalation）三级值班
- 排班以周为单位，交接需在值班群同步当前已知问题/风险点

## 2. 告警响应 SLA
- P0 告警：5 分钟内一线必须响应（Ack）
- P1 告警：15 分钟内响应
- 一线超时未响应，系统自动升级通知二线

## 3. 联系不上负责人时的升级路径
1. 一线通过电话 + IM 双渠道联系，等待 5 分钟
2. 仍无响应 → 自动/手动升级到二线值班
3. 二线也无响应（15 分钟内）→ 升级到经理层，同时拉相关技术负责人进事件群
4. 涉及重大客户影响或安全事件，可直接跳过分级，升级到 P0 事故响应流程

## 4. 升级判断标准
- 影响范围扩大、无法在预期时间内止血
- 涉及资金安全、数据泄露、重大合规风险
- 需要跨团队协作但无法自行推动

## 5. 值班工具与记录
- 使用统一的告警/排班工具（PagerDuty 或等效系统）
- 每次告警处理需记录响应时间、处理过程、是否升级，便于复盘值班质量
