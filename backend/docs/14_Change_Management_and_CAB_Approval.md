# 变更管理与 CAB 审批（Change Management）

## 1. 变更分级
- **标准变更**：低风险、有既定流程（如日常发布），可预授权，无需逐次审批
- **常规变更**：中等风险，需要变更单 + 至少一名 Owner 审批
- **重大变更**：高风险（涉及数据库结构、核心权限、网络策略、生产集群配置），必须走 CAB（Change Advisory Board）评审

## 2. 变更单必填字段
- 变更内容、影响范围、回滚方案
- 计划执行时间窗（避开业务高峰期）
- 风险评估与应急预案
- 审批人与执行人（建议分离）

## 3. CAB 评审流程
1. 提交变更单，附带风险评估与回滚方案
2. CAB 成员（技术负责人、安全、SRE）线上或例会评审
3. 通过后进入变更日历，指定执行窗口
4. 执行后 24 小时内提交执行结果与观察报告

## 4. 常见需要 CAB 审批的场景
- 生产数据库结构变更、大规模数据迁移
- 防火墙/网络策略变更、VPC 对等连接调整
- API 配额/限流策略的重大调整
- 权限模型（RBAC）重构

## 5. 紧急变更（Emergency Change）
- 仅用于止血类操作（如安全漏洞修复、P0 事故处理）
- 可先执行后补审批，但必须在 24 小时内补齐变更单
